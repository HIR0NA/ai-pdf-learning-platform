1. ข้อมูลโครงการและวัตถุประสงค์ (Project Overview)

ระบบ AI PDF Learning Platform (AgentAI) เป็นแพลตฟอร์มการเรียนรู้ที่เปิดโอกาสให้นักศึกษาอัปโหลดเอกสารประกอบการเรียน (PDF) ขนาดใหญ่สูงสุด 50MB เพื่อวิเคราะห์ สรุปเนื้อหา ถาม-ตอบอัจฉริยะแบบเรียลไทม์ (Contextual Chat Streaming) และสร้างเครื่องมือช่วยจำ เช่น แบบทดสอบ (Quiz), บัตรคำ (Flashcard) และตารางอ่านหนังสือ (Study Schedule) โดยเชื่อมต่อกับโมเดลปัญญาประดิษฐ์ชั้นนำ (Google Gemini, Groq GPT-OSS 120B และ Qwen) พร้อมการแยกจัดเก็บข้อมูลส่วนบุคคลอย่างปลอดภัย

2. การระบุ Asset สำคัญและการวิเคราะห์ Attack Surface

2.1 การระบุ Asset สำคัญของระบบ (Critical Assets)

Asset รายละเอียดและข้อมูลที่เก็บรักษา ระดับความสำคัญ ผลกระทบหากรั่วไหล
User Identity & Credentials ข้อมูลบัญชีผู้ใช้, รหัสผ่านที่เข้ารหัสด้วย Bcrypt (Cost 12), Session JWT Token Critical การสวมรอยบัญชี / Account Takeover
Private Stored PDFs ไฟล์เอกสาร PDF ต้นฉบับที่ผู้ใช้อัปโหลด จัดเก็บในไดเรกทอรีเฉพาะ uploads/ Critical ข้อมูลข้อสอบ/เอกสารลับรั่วไหล (Data Breach)
Database (PostgreSQL) ตารางข้อมูล User, Document, Message, LearningTool, LoginLog Critical ข้อมูลทั้งระบบถูกดึงหรือแก้ไขผ่าน SQL Injection
AI API Keys คีย์ลับ GEMINI_API_KEY, GROQ_API_KEY, BAZAARLINK_API_KEY High การถูกขโมยโควตาใช้งานจนเกิดค่าใช้จ่ายสูง (Denial of Wallet)
Web Application Server Next.js 16 Framework, Turbopack Engine และ Route Handlers High บริการล่มจากการโจมตี DoS หรือการรันโค้ดอันตราย (RCE)

2.2 การวิเคราะห์พื้นผิวการโจมตี (Attack Surface Analysis)

  • Authentication Endpoints (/login, /register): สุ่มเสี่ยงต่อ Password Brute-force, Credential Stuffing และ SQL Injection ผ่านฟอร์มกรอกข้อมูล
  • Document Upload API (/api/upload): รับไฟล์ Multipart Form Data ขนาดสูงสุด 50MB เสี่ยงต่อ Arbitrary File Upload, Path Traversal (../../) และ Fake MIME Type
  • Files Access API (/api/files/[filename]): เสี่ยงต่อ Broken Object Level Authorization (BOLA/IDOR) ที่ผู้ใช้หนึ่งอาจพยายามดาวน์โหลดไฟล์ของผู้อื่น
  • AI Chat & Tool Endpoints (/api/ai, /api/tools): รับ Input ข้อความ เสี่ยงต่อ Prompt Injection, Resource Exhaustion (DoS) และ Rate Limiter Bypass
  • Admin Console & API (/admin, /api/admin/*): เสี่ยงต่อ Privilege Escalation และ Missing Function Level Access Control จากผู้ใช้ทั่วไป

4. การประยุกต์ใช้เทคโนโลยี/เครื่องมือในวงรอบ DevSecOps (Tool → Detect → Analyze → Fix)

1. Dependency Scanner: npm audit Detection & Remediation
[Detect]: สแกนพบช่องโหว่ High Severity ใน browserslist ≤4.28.6 (GHSA-c83g-rgw3-j3cx: Unbounded memory growth / Prototype write)
[Analyze]: มีความเสี่ยงต่อการเกิด Denial of Service (Out of Memory) ระหว่างการประมวลผล Build / Compilation
[Fix]: ดำเนินการแก้ไขด้วยคำสั่ง npm audit fix เพื่ออัปเดต dependency graph และ package-lock.json
[Retest]: สแกนซ้ำยืนยันผล found 0 vulnerabilities (ดูหลักฐานใน evidence/sast/npm-audit-report.md)
2. Web Application Security Testing: Burp Suite Dynamic Testing (DAST)
[Detect]: ดักจับ Request ไปยัง GET /api/admin/overview ด้วยสิทธิ์บัญชี STUDENT
[Analyze]: พบช่องโหว่ Broken Access Control โดยระบบเดิมตอบกลับ HTTP 200 OK พร้อมข้อมูลสถิติของแอดมิน เนื่องจากตรวจสิทธิ์เฉพาะที่ UI
[Fix]: ติดตั้ง RBAC Guard ที่ Edge Proxy (src/proxy.ts) และ Route Handler ตรวจสอบบทบาท ADMIN จาก Session Token จริง
[Retest]: ยิง Request ซ้ำ ระบบตอบกลับ HTTP 403 Forbidden ทันที (ดูหลักฐานใน evidence/burpsuite/admin-rbac-403.txt)
3. Vulnerability Scanner: OWASP ZAP Automated Baseline Scan
[Detect]: ZAP แจ้งเตือน Missing Security Headers (CSP, nosniff, frame-ancestors) และ Cookie Flags
[Analyze]: ทำให้แอปพลิเคชันมีความเสี่ยงต่อ Clickjacking, MIME Confusion Attacks และ Cookie Sniffing
[Fix]: เพิ่ม Security Headers ครบถ้วนใน next.config.ts และตั้งค่า NextAuth Cookie Flag (httpOnly, sameSite: "lax", secure)
[Retest]: สแกนซ้ำพบว่า Security Headers ถูกต้องครบถ้วนและ Alert ลดลงเหลือศูนย์ (ดูหลักฐานใน evidence/zap/zap-scan-report.md)
4. Automated Security Unit Testing: Node Native Test Runner Regression & SAST Testing
[Detect & Verify]: รันชุดทดสอบความปลอดภัยอัตโนมัติ (tests/security.test.ts และ tests/rbac.test.ts)
[Coverage]: ตรวจสอบ Path Traversal, IP Spoofing, In-memory Rate Limiting, HTTP 413 Oversized Payload และ Regression Auth Bypass
[Result]: ผ่านการทดสอบทั้งหมด 10/10 Test Suites (100% Pass) รับประกันความปลอดภัยในทุก Release

5. หลักฐานการเปรียบเทียบก่อนแก้และหลังแก้ (Before / After Evidence)

จุดที่ 1: การอัปโหลดไฟล์, ตรวจสอบ Magic Bytes และป้องกัน Path Traversal

❌ ก่อนแก้ไข (Vulnerable - เชื่อถือชื่อไฟล์ Client) 
// เชื่อถือ MIME จาก Browser โดยตรง
if (file.type !== 'application/pdf') return error;

// นำชื่อไฟล์จาก Client ไปต่อ Path ตรงๆ
const filePath = path.join(uploadDir, file.name);
// เสี่ยงต่อ Path Traversal เช่น "../../package.json"
await fs.writeFile(filePath, buffer);
✅ หลังแก้ไข (Secured - ตรวจ Magic Bytes + UUID v4) 
// ตรวจ Magic Bytes 4 ไบต์แรก (%PDF- / 0x25 0x50 0x44 0x46)
const isRealPdf = buffer[0]===0x25 && buffer[1]===0x50;
if (!isRealPdf) return error('Magic bytes mismatch');

// สุ่มชื่อไฟล์ใหม่เป็น UUID v4 และกักบริเวณ Path
const safeFilename = `${crypto.randomUUID()}.pdf`;
const { pdfPath } = resolveStoredDocumentPaths(safeFilename);
await fs.writeFile(pdfPath, buffer);

จุดที่ 2: การควบคุมสิทธิ์เข้าถึงหน้าและ API ของผู้ดูแลระบบ (Admin RBAC)

❌ ก่อนแก้ไข (Vulnerable - ซ่อนปุ่มเฉพาะหน้า UI) 
// src/components/Navbar.tsx
// ซ่อนปุ่มเมนูเท่านั้น แต่นักเรียนยิง API ตรงได้
{session?.user.role === 'ADMIN' && (
  Admin Console
)}

// GET /api/admin/overview ไม่มีการตรวจสิทธิ์
export async function GET() { return NextResponse.json(stats); }
✅ หลังแก้ไข (Secured - ตรวจสิทธิ์ระดับ Edge Proxy & Route) 
// src/proxy.ts (Edge Proxy Guard)
if (pathname.startsWith('/api/admin')) {
  if (token?.role !== 'ADMIN') {
    return NextResponse.json({ error: 'Forbidden' }, { status: 403 });
  }
}
// Server Route Handler ตรวจสอบซ้ำและปฏิเสธด้วย 403
if (!isAdmin(session.user.role)) return forbidden();

จุดที่ 3: ระบบป้องกันการเดารหัสผ่าน (Brute-Force Attack & Account Lockout)

❌ ก่อนแก้ไข (Vulnerable - เดารหัสผ่านได้ไม่จำกัด) 
// ตรวจรหัสผ่านผ่าน Bcrypt ปกติ
const isValid = await bcrypt.compare(pass, user.password);
if (!isValid) {
  // ไม่มีตัวนับความล้มเหลว สามารถยิงสุ่มรหัสผ่านได้เรื่อยๆ
  return null;
}
✅ หลังแก้ไข (Secured - ล็อกบัญชี 30s เมื่อผิด 5 ครั้ง) 
// ตรวจสอบสถานะล็อกบัญชี
if (user.lockedUntil && user.lockedUntil > new Date()) {
  throw new Error(`LOCKED:${remainingSeconds}`);
}
// นับ failedAttempts หากครบ 5 ครั้ง กำหนดเวลาล็อก
const shouldLock = (user.failedAttempts + 1) >= 5;
await prisma.user.update({ data: { failedAttempts, lockedUntil } });
await prisma.loginLog.create({ data: { email, ip, success: false } });
